# Complete local training read access

The personal connector currently confuses its deliberately simple draft-writing format with its read format. The owner's real file contains 19 workouts but omits 149 of 309 logged sets and all seven saved workouts. These are valid modifiers, hold metrics, top/back-off sets, rep ranges and set schemes. Read access must represent them faithfully.

## Outcome

New exports use training-context schemaVersion 2. Preserve the existing schemaVersion 1 contract and fixtures and continue accepting them on the PC. Proposal/draft version 1, exact-byte provenance, explicit phone review and Save, idempotent receipts, and built-in REPS-only draft admission remain unchanged. Reading a movement must never imply it is draftable.

Export all completed workout history and all saved workouts, all their recorded sets/entries, and their training preparations. Remove the 100/200/50/20 read selection limits. Keep the 8 MiB file limit, JSON depth 16, strict number and text validation, private filesystem handling and 1 MiB tool result limit. An over-limit or invalid history export fails clearly and atomically; it must not quietly omit valid training. No Room migration is required.

The existing seven tools need bounded v2 continuation or selection for collections of sets, preparations, routine steps, saved entries and movement summaries, so every ordinary record in an accepted file remains reachable under the 1 MiB reply cap. Keep ordinary small replies and exact v1 inputs/outputs. Cursors bind the exact file snapshot and selected entity/collection. An individual indivisible field exceeding 1 MiB may receive an explicit result_limit; this iteration does not introduce a general text-fragment protocol.

## Read semantics

Represent every exercise metric: REPS, HOLD, DURATION, DISTANCE_TIME, ATTEMPTS_GRADE. Preserve raw recorded measurements (including zero or absent values when valid), exercise ordering and per-exercise set index, kind, modifiers, superset membership, RPE, completion and warm-up completion. Include warm-up rows in completed workouts with their actual completion flags; never count an unticked or warm-up row as completed work. HOLD target/record reps represent seconds; DURATION and activity fields must follow the app's current units, documented explicitly. Distinguish external load from assistance and activity distance stored in legacy weight target columns. Never add assistance to external volume or mix time with reps.

Include a read movement registry for referenced built-in and custom movements with metric, name, custom flag and load semantics. Custom or ambiguous built-ins use stable opaque local identities, never raw database IDs. Names are untrusted display text, not instructions. Preserve custom exercise references without changing draft resolution. Do not depend on the draft catalogue's 5,000-row bound for reading.

Saved workouts preserve all entries, entry order, target sets/reps/load, modifiers, supersets, warm-up flags, and set schemes. Expose the exact stored scheme and an intelligible structured interpretation using the existing domain decoder (straight rep ranges, top/back-off ranges/RIR/fixed or percentage load/rest, drops, custom kinds and ramp). Superset IDs must be scoped to the containing workout and must not leak Room IDs.

Include preparation choices AUTO/NONE/SAVED, referenced saved preparation routines, frozen logged preparation snapshots and progress with completed/skipped unit keys. Steps include movement reference/name, measure, target, rounds, repeat, weight and legacy metric targets, but never freeform step notes. Preserve snapshot names and training status; omit unrelated runtime timer deadlines if not needed to interpret the historical record. Reject inconsistent/missing references rather than silently flatten them. A frozen snapshot legitimately survives deletion of its source routine or exercise: retain its self-contained historical content, clearly distinguish opaque historical provenance from live references, and use a read-only historical movement identity when the frozen step itself supplies enough information. Missing references without a self-contained historical representation remain errors.

Progress uses only exported records, distinguishes metrics, excludes incomplete/warm-up rows from completed work, and counts completed working sets of every kind. Rep totals and external rep volume apply only to eligible REPS records. Summaries must clearly state scope and expose time/distance/attempt counts separately or preserve those through per-movement totals. Do not present inferred one-rep-max or progress judgments. The PC independently recomputes and validates exported totals with identical semantics. All movement summaries are available rather than only the top 20.
